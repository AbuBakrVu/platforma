## Как идёт работа с git
- Каждая порция — новая ветка от свежего `main` (`git checkout main && git pull && git checkout -b <имя>`).
- **Не коммитить, пока пользователь не попросит.** Обычно он нажимает «Create PR» в приложении — тогда коммит, push, `gh pr create` (не draft).
  Тело PR — на русском, с разделами «Что изменилось», «Миграция», «Проверено».
- Пользователь сам мёржит. После мёржа он спрашивает, как обновить сервер.
- Сеть иногда тормозит: при таймауте `gh`/`git push` — проверить состояние и повторить.

## Сервер
- Сайт **https://pl.bakr.pro**. Хост `nasiya`, проект в **`/root/platforma`**, вход под root (sudo не нужен).
- Рядом работают CRM пользователя (`/opt/crm`, контейнеры `crm` :3000 и `nasiya-app` :3100) — не мешать им.
  Порты 80/443 держит Caddy, установленный на хосте (systemd); `install.sh` дописывает свой блок в его Caddyfile.
- Приложение платформы слушает **127.0.0.1:3101** (APP_PORT в `.env`).
- Обычное обновление: `cd /root/platforma && git pull && docker compose up -d --build` (миграции применяются сами, контейнер `migrate`).
- Если в PR появились новые настройки (.env, nginx/Caddy) — вместо этого `./install.sh` (повторный запуск безопасен, спросит домен/админа заново).
- Почта (SMTP) настраивается через `./install.sh`; без неё регистрация без подтверждения, пароль сбрасывает администратор.
- Проверка: `curl http://127.0.0.1:3101/api/health` → `{"ok":true}`.
- На сервере загружены демо-данные (помечены `demo`, удаляются кнопкой на главной у администратора, когда пользователь решит).
- Docker локально нет — образы и лаборатории в Docker-режиме проверяются только на сервере.
- Лаборатории (профиль `labs`) на сервере **не включены**: им нужен docker.sock, рекомендуем отдельную машину (README → «Лаборатории»).
- Магазин: после установки нажать «Добавить стандартный набор» в меню «Магазин и игра».

### Интерфейс
- Меню (`components/Sidebar.tsx`) разное для ролей; группы с заголовком сворачиваются (раскрыта та, где текущая страница;
  в свёрнутой — сумма счётчиков). ученик (учёба / игра / общение), сотрудник (рабочие разделы по правам,
  без игры), родитель. Раздела «Управление» и ряда вкладок больше нет: страницы `/admin/*` открываются из меню сотрудника,
  `/admin` перенаправляет на главную. Главная сотрудника — `components/StaffHome.tsx` («что сделать сегодня»).
- Раздел «Люди и потоки» — вкладки `components/PeopleTabs.tsx`; роль, поток, пароль меняются в карточке человека `/admin/people/[id]`.
- На телефоне (≤860px): верхняя строка с кнопкой меню, выезжающее меню, нижняя панель (`.mbar`, `.mtabs` в globals.css).
- Регистрация открытая (`/register`, по почте и телефону; без кода — ученик без потока, видит только «ждите», курсы — только выданные лично),
  вход по почте или телефону (`lib/phone.ts` → `+79281234567`), коды подтверждения и сброса (`lib/codes.ts`), письма (`lib/mail.ts`, SMTP_* в .env;
  локально `SMTP_HOST=console` — письма в журнал dev-сервера). До подтверждения почты `requireUser` ведёт на `/verify`.
  Политика конфиденциальности и данные организации — таблица `settings` (`lib/settings.ts`), страница «Настройки» только у администратора.
- **Разделы-переключатели** (`lib/features-list.ts`, `lib/features.ts`, «Настройки» → «Разделы платформы»): расписание и посещаемость,
  наставники, чат потока — сейчас **выключены** по решению пользователя (нет живых занятий). Выключенный раздел скрыт в меню
  (`feature` у пункта в Sidebar), на главных и в карточке человека; его страницы перенаправляют на главную. Новые места —
  проверять `featureOn(...)`. Данные не удаляются.
- Курсы у сотрудника: «Курсы» (карточки с обложкой, `components/CourseCover.tsx`) и «Создать курс» (`/admin/courses/new`).
  Обложка — `courses.cover_id` (картинка из загрузок курса), переносится в архиве курса.
- Слова: «ученик» (не «студент»), «сотрудник» (не «персонал»), «Мои курсы», «Задания дня».

### Ключевые модули `web/src/lib`
- `auth.ts` — сессии, `getUser` (с правами `perms`), `requireUser({ parents })`, `requireInternal`, `requireStaff`, `requirePerm`, `can`, вход под пользователем.
- `permissions.ts` — 10 прав, роли по умолчанию, `isStaff`/`isStaffRole` (можно в клиентских компонентах).
  **Никогда не проверять «персонал» как `role !== "student"`** — есть роль `parent`. Только `isStaff()` / `can(user, perm)`.
- `queries.ts` — доступ к курсам (`getMyCourses`, `canAccessCourse`, программы, личные курсы внешних учеников, блокировки), структура курса.
  Функции доступа принимают узкий тип `Learner` (id, role, groupId, external).
- `steps.ts` — типы шагов урока; `markdown.ts` — Markdown для персонала (KaTeX, вставки);
  `md-visual.ts` — мост Markdown ↔ визуальный редактор (`components/VisualEditor.tsx`, Tiptap). Новые конструкции Markdown
  добавлять в оба файла, иначе визуальный режим их потеряет (или пометить в `visualUnsupported`);
  **`user-md.ts` — безопасный Markdown для текстов пользователей** (комментарии, форум, чат) — использовать его для всего, что пишут ученики.
- `gamify.ts` (`award()` — единая точка начисления XP/монет), `achievements.ts`, `leagues.ts`, `quests.ts`, `shop.ts`, `duels.ts`.
- `community.ts`, `chats.ts`, `news.ts`, `kb.ts`, `parents.ts`, `labs.ts`, `packages.ts` (SCORM), `transfer.ts` (экспорт курса), `storage.ts`.

### Известные грабли
- Даты из сырых SQL-агрегатов (`sql<Date>\`max(...)\``) приходят **строкой** — оборачивать в `new Date()`.
- Date в параметрах сырого `sql\`\`` — передавать `.toISOString()` + `::timestamptz`.
- React 19 сбрасывает форму после server action: формы массового назначения пересоздавать через `key` от данных.
- Пути с переменными в `storage.ts`/`transfer.ts` помечены `/*turbopackIgnore: true*/`, иначе сборка тащит загрузки в standalone.
- Время в рендере (`Date.now()`) линтер запрещает — выносить в функции модуля.
- Страница, которая читает базу, но не трогает cookies/searchParams (например, публичная `/privacy`), собирается заранее при
  `next build` — в Docker базы нет, сборка падает. Ставить `export const dynamic = "force-dynamic"`. Проверка перед PR:
  `DATABASE_URL=postgres://build:build@localhost:5999/build npx next build` (база недоступна, как в Docker).

## Локальная разработка и проверка
- Postgres 16 через brew, `web/.env.local` (DATABASE_URL, SEED_DEMO_PASSWORD, LAB_* для лабораторий).
- `.claude/launch.json`: `web` (порт 3100) и `labs` (порт **3210**, режим `local`; порт 3200 занят другим приложением пользователя).
- Проверки перед PR: `npx tsc --noEmit`, `npm run lint`, `rm -rf .next && npm run build` (лучше с недоступной базой, см. грабли), миграции и сид на чистой базе
  (`createdb platforma_fresh_test` → migrate → seed → `dropdb`).
- Тестовый вход без паролей: создать сессию SQL-ом (токен → sha256 в `sessions.id`) и поставить cookie `session` через JS.
  Защищённую (httpOnly) cookie, выданную сервером, JS не перезапишет — сначала «Выйти».
- Если панель браузера скрыта — скриншоты не работают, `document.hidden = true` (опрос чата на паузе); проверять через `read_page`/JS.
- После проверок удалять тестовые данные и сессии из локальной базы.
